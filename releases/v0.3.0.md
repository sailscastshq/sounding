# Sounding 0.3.0 — real Sails hook fixtures

Sounding now supports isolated tests inside reusable Sails hook packages through
`sounding-plugin-hook`. Install the plugin as a development dependency, keep the
normal `require('sounding').test` import, and assert behavior against the real
hook mounted in a fresh Sails instance.

## Package versions and installation

- `sounding`: **0.3.0**, with pre-boot plugin preparation and lifecycle fixes.
- `sounding-plugin-hook`: **0.1.0**, the first public hook fixture plugin.
- `sounding-plugin-stress`: **0.1.1**, a peer compatibility patch accepting
  Sounding `^0.2.0 || ^0.3.0`; no stress engine behavior change.

```sh
npm install -D sounding@^0.3.0 sounding-plugin-hook@^0.1.0 sails@^1.5.18
```

The plugin is discovered from the hook package's dependencies/devDependencies.
No plugin registration array or separate test import is needed. Run tests with
`npx sounding test` or `node --test test/*.test.js`.

## A meaningful hook contract

This example was executed against real Shipwright 1.5.1
(`f233659eb9749157f78fd84e780175f96b95bbe0`), Sails 1.5.18 and Node 24.14.1:

```js
const { test } = require('sounding')

test('emits initial asset tags without eager-loading async chunks', {
  hook: { config: { dontLift: true }, files: {
    '.tmp/public/manifest.json': JSON.stringify({ entries: { app: {
      initial: { js: ['/js/app.a1b2.js'], css: ['/css/app.c3d4.css'] },
      async: { js: ['/js/settings.e5f6.js'] }
    } } })
  } }
}, async ({ sails, hook, expect }) => {
  expect(hook.scripts()).toBe('<script src="/js/app.a1b2.js"></script>')
  expect(hook.styles()).toBe('<link rel="stylesheet" href="/css/app.c3d4.css">')
  expect(sails.config.views.locals.shipwright.scripts()).toBe(hook.scripts())
  expect(sails.config.dontLift).toBe(true)
})
```

The supplied manifest is controlled test input. This verifies manifest consumption,
HTML output and view-local integration; it does not claim to run Rsbuild or a
browser. `dontLift: true` explicitly skips Shipwright's build/dev-server startup.
Plain Sails.load does not supply that flag in this fixture.

## What changed

- Fresh temporary app and hook instance per trial; config overrides and fixture
  file contents are applied before boot. Existing fixture content can be copied
  without editing its source.
- `{ hook }` is the actual `sails.hooks[hook.identity]`; `hook.name` is a read-only
  identity alias. `{ hookApp }` exposes fixture/package metadata.
- Default load selects minimal non-ORM hooks. HTTP trials promote to lift, with
  loopback binding and an ephemeral port. Other hook dependencies are explicit.
- Workspace peers resolve the local core during contributor installation, avoiding
  accidental installation of an older registry copy or fetching an unpublished version.
- Plugins may declare trial options and prepare a runtime/context/cleanup before
  runtime resolution. Multiple runtime owners and replacing explicit runtimes
  reject with cleanup of prepared resources.
- `createAppManager({ loadOptions })` supports constructor overrides. Lower waits
  for active load/lift, attempts both instances and restores manager state.
- Cleanup runs after handler and boot failures, closes resources before Sails
  lower, and removes fixture directories. Combined trial/cleanup failures remain
  visible through AggregateError.

## Upgrade and limits

Cleanup failures that were previously swallowed now reject. Callers manually
managing lifecycles should await and handle `lower()`; automatic trials report the
failure normally. This reliability change and the additive hook API motivate the
pre-1.0 minor version.

Hook fixtures support only direct mounting and fresh instances. Concurrent hook
trials reject with `E_SOUNDING_HOOK_CONCURRENCY`. `test.hookFails`,
`test.hookFactory`, package/api-hooks mounts, warm reuse and additional matchers
remain follow-ups in #101. This release does not close all of that issue.

Views/ORM/socket dependencies require explicit configuration. The default excludes
ORM and connects no database; a placeholder datastore config satisfies the core
runtime. A true datastore-disabled core mode remains follow-up work. Browser/socket
hook lifecycle integrations were not measured or verified for this release.

## Performance evidence

Eight alternating fresh processes per version on macOS arm64, Node 24.14.1 and
Sails 1.5.18 measured the same minimal real-hook lifecycle workflow:

| Median, milliseconds | Main 0.2.0 | Hook implementation |
| --- | ---: | ---: |
| Complete process/workflow | 240.977 | 241.473 |
| First Sails load after imports | 35.684 | 35.816 |
| Warm app reuse | 0.020 | 0.020 |
| Isolated reload including lower | 4.955 | 5.038 |
| Load cleanup | 0.095 | 0.117 |

The approximately 0.21% total difference supports **no speedup claim**. Isolation
and cleanup remain included. HTTP lift samples followed virtual load with warm
module caches. Shared-runtime concurrency microbenchmarks contain no shared
mutations and do not establish safe parallel hook lifecycles. Browser timings
remain unmeasured.

Raw measurements and reproduction commands are in `bench/`; the dated benchmark
report records its original unpublished snapshot. The keynote benefit is a small,
real hook test with owned setup and cleanup, not a faster measured runtime.

## Validation and release gates

The implementation passed 173 unit/integration tests and JavaScript type checking,
plus real Shipwright source and packed-package demos. An intentional failing
node-fetch demo exited 1 while the next isolated trial and final cleanup checks
still ran. CI now runs tests, type checking and package packing on Linux/macOS
with Node 24; the draft PR records actual CI status separately.

versions and the annotated core tag `v0.3.0` require release-owner approval. No tag
